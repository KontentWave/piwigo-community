## High-risk coupling rules

- Never grant core admin status to represent a Community capability.
- Authorization must happen before core upload/category/tag writes, for every destination and object, including replacement, format attachment, and update modes.
- Validate `original_sum` as exactly 32 hexadecimal characters before filesystem or database use; escaping remains mandatory at each sink, including the Community post-upload checksum lookup and filename uniqueness precheck.
- Plugin table and image/category/filesystem transitions need one recoverable workflow.
- Stateful upload code must acquire its stable upload lock before the Community quota user-row lock; no path may invert this order.
- Community `pwg.images.upload` accepts only one validated multipart file. Raw-body/core append-chunk compatibility belongs to administrators/core bypass paths, not Community actors.
- Changes to Piwigo webservice registration, handler priority, upload response shape, token rules, user status semantics, or category schema require Community regression tests.
- Upload completion must never delegate Community requests to global `empty_lounge()`; preserve exact `(image_id, category_id)` scoping, canonical hook payloads, stable lock inodes, and compatibility for both public method names.
- Changes to Two Factor helper names, bootstrap constants, profile URL semantics, or webservice policy require an explicit compatibility review.
